一、先更新 Google 試算表後台
1. 開啟原本收回覆的 Google 試算表 →「擴充功能」→「Apps Script」。
2. 用新版 Code.gs 取代原程式並儲存。
3.「部署」→「管理部署作業」→ 編輯原網頁應用程式 → 版本選「新版本」→「部署」。
4. 執行身分維持「我」，可存取的人維持「所有人」；依畫面完成所需授權。
5. 沿用原部署作業通常可維持 /exec 網址；若另建部署，請同步更新 index.html 的 SCRIPT_URL。

重要：新增狀態需要新版 Code.gs。只儲存程式、沒有部署「新版本」，公開端點仍會使用舊的三種狀態檢查，新增狀態將無法寫入。
本版保留「回覆紀錄」四欄：送出時間／選擇狀態／想說的話／請求 ID。無須重建試算表；既有資料與三種舊狀態仍相容。

二、更新 GitHub Pages
1. 上傳或取代 index.html 與全部四張照片，檔案放在同一層，名稱須完全一致。
2. Code.gs 不必上傳 GitHub；README.txt 可留作本機維護說明。
3. 等候 Pages 更新後，以 Ctrl+Shift+R 重新整理。
4. 點選任一狀態，確認直接展開小信；送出近況後，以網站顯示後台確認的成功回條為準。
5. 在試算表確認新紀錄的狀態、留言與請求 ID。網路失敗重試沿用原 ID，避免重複寫入。

三、問題排查
- 新增狀態無法送出：先確認 Code.gs 已部署「新版本」，且 SCRIPT_URL 指向該部署的 /exec。
- 等不到後台確認：檢查部署存取權、網路及 Apps Script「執行項目」的錯誤。
- 試算表沒有資料：確認腳本從正確試算表開啟；查閱 Apps Script 執行紀錄。
- 圖片缺失：四張照片須與 index.html 同層，名稱與大小寫一致。
- 本機 HTML 可預覽外觀；完整的跨網域收件與確認需於實際部署環境驗證。

四、維護與資料處理
- SCRIPT_URL 為公開提交端點；本版沒有身分驗證，回覆不代表已確認特定人的身分。
- 寫入使用 POST，收件確認使用 JSONP GET；查詢只回傳該隨機請求 ID 的收件結果，不回傳留言。
- 留言仍限制 120 字；後台保留控制字元與試算表公式防護。
- Apps Script 與 Google 試算表有流量及執行限制；照片公開展示前請確認有使用權。
- 改文案可搜尋 hero-title、letters、fortunes；改配色可搜尋 :root。
- 更新 HTML 或照片後重新上傳 Pages；更新 Code.gs 後須另部署新版本。
